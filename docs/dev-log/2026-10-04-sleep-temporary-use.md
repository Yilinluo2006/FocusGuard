# 睡眠模式临时使用

用户要求取消睡眠模式的直接提前退出，改为每次连续临时使用 2 分钟，手机和平板共用 5 次。次数按睡眠计划开始所属的额度日计算；同一段跨午夜、跨凌晨 04:00 的计划不会中途补发，下一轮额度日的睡眠计划恢复次数。

## 实现

- 睡眠管控覆盖层和计划页均改为“临时使用 2 分钟”，显示剩余次数、申请状态和计时；用完禁用申请。旧 `sleepFinish` 操作与 `FocusModeStore.finishEarly` 睡眠分支均拒绝永久提前结束。
- 临时使用只暂停当前设备的睡眠覆盖层，原计划结束时间、记录和应用每日额度保持运行。两分钟到后控制器重新启用覆盖层；锁屏、切换应用不暂停计时，重启使未结束的临时放行失效。电话和白名单入口保留。
- 已启用同步的睡眠段固定使用共享规则，中途关闭同步也不能退回独立的五次额度。新申请需要联网，已确认的两分钟可以离线继续。未配置同步的单设备使用持久化本地五次额度。
- 后端新增 `GET/POST /api/sync/sleep/temporary/{device}`；校验登录账号、设备 UUID 和当前有效共享计划，按账号锁串行扣次，持久化 `sleep_temporary_grants`。最多五次，之后返回 HTTP 429，没有永久放行后备操作。
- 请求 UUID 在客户端持久化，网络失败显式重试同一编号。重试不重复扣次、不延长已签发的区间；同设备已有放行时重复点击返回原区间。过期确认不会在客户端重新开始计时。网络请求在主进程后台线程执行。
- 临时使用记为 `temporary_use` 的未保护区间，睡眠计划不因此写成主动提前解除，也不直接中断坚持记录。

## 验证与交付

- 后端新增 5 项 SleepTemporaryIntegrationTests 全部通过，覆盖两端共用五次、第六次拒绝、请求重试与重复点击、凌晨 04:00 跨界、下一夜恢复、账号隔离、计划结束截断、两端同时争取第五次。原 DeviceSyncIntegrationTests 5 项也通过，使用独立测试数据库。
- JVM 24 项通过：SleepTemporaryPolicyTest、RestrictionRulesTest、SleepControlTimelineTest、SharedQuotaPolicyTest。控制器使用同一政策方法，验证 120 秒边界恢复管控、重启、改时和次数上限。
- OPPO Pad 5 隔离 `.setupprobe` 包 5 项通过，验证持久化扣次、保持原睡眠结束时间、旧提前结束拒绝、五次耗尽、计划页真实视图，以及过期服务端确认不重新放行。首次 UI 测试发现 FocusModeActivity 在独立 guard 进程；改为隔离测试专用 Activity 承载实际 FocusModePage，未更改产品进程配置。测试包已卸载。
- 最终 APK 已覆盖安装手机 470e575c 和平板 YHCQSSEYTSVODMZD，保留用户数据。手机在最后更新时 USB 中断，用户重新连接后已完成补装并恢复 ADB reverse。本地后端已更新并启动，新表属于增加结构。
- 后端首次打包因运行中 JAR 被占用而无法重命名；这一步已把构建产物换成普通 JAR，因此该文件不是真正的旧版备份，已改名 target/server-sleep-build-unpackaged.jar 留供诊断。停止确认过的本地服务后重新打包、启动并验证健康。另从当前可执行 JAR 中去除新增睡眠类，重建 target/server-without-sleep-temporary.jar 作为回退包，验证 ZIP 完整性及可执行结构；未实际启动这个回退包。
- 两端认证访问新状态接口，在当前未进入睡眠计划时均返回预期 HTTP 409，未申请或消耗用户的真实次数。配置检查仍为同账号、版本 5、三个任务、九条限制、23:30 开始 / 240 分钟的原计划。
- 没有为测试修改用户手机和平板的实际睡眠时间，也没有将时间推进模拟称为真实整晚或两分钟覆盖层实测。实际睡眠段里的覆盖层恢复仍需在正常使用中观察。

后端仍是电脑本地服务，依靠 ADB reverse。公网部署前，设备离开电脑后无法申请新的共享临时使用时间。
