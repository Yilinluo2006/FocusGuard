## 用户流程

登录页保留邮箱、手机号入口，新增微信登录。用户确认说明后，由后端创建短期随机请求，客户端再启动微信原生授权。
已有账号先用邮箱或手机号登录，在个人资料中绑定微信；绑定后仍使用原 userId，原备份与同步归属不变。
尚未绑定的微信首次登录会创建新账号。不会按微信昵称、邮箱或相同头像猜测并合并账号。
微信若属于另一账号，绑定返回冲突；暂不提供更换或解绑微信入口。
仅微信登录的新用户可以先绑定手机号，再设置邮箱与密码；原邮箱/手机号登录路径保持可用。

## 授权安全与数据

- 客户端仅发回微信 code 与后端生成的 state。后端固定访问微信 HTTPS 接口，交换并核对 OpenID/UnionID。
- 微信 access_token 与 refresh_token 不返回客户端；客户端保存奶蛙自己的 JWT。
- 请求绑定目的、账号、服务器、开机标识和五分钟有效期；重复、过期、错误目的、换账号及重启后的回调被拒绝。
- 后端先原子消费 state，再访问微信；上游失败也不能复用同一请求。
- 身份通过数据库唯一约束关联同一账号，微信登录独立于邮箱是否验证，不使用伪造邮箱。
- 微信回调入口无有效待授权请求时不初始化 SDK；SDK 日志不记录授权码或提供者响应。
- 用户取消、未装微信、能力或密钥未配置、授权失败时没有登录成功状态，可以返回使用原有方式。
- 昵称仅用于新微信账号，既有账号的昵称和奶蛙头像不会被微信资料覆盖。

## 后端接口

- `POST /api/auth/wechat/start`
- `POST /api/auth/wechat/login`，请求体为 `{code,state}`
- `POST /api/account/bindings/wechat/start`，需要现有 JWT
- `POST /api/account/bindings/wechat/confirm`，需要现有 JWT 和 `{code,state}`

校验通过但密钥未配置时，开始授权返回 503，客户端显示微信登录暂不可用，不伪造成功。
开发包仍使用电脑本地后端，通过 USB 反向端口访问；正式两端登录需要部署可访问的 HTTPS 后端。
