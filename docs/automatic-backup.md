# 账号自动备份（2026-09-30）

## 使用

设置 → 账号与备份 → 登录/注册 → 开启自动备份。首次开启会说明上传范围，并立即上传一次。
无需为了日常保存反复点击备份；「立即备份」用于检查连接或主动重试。
同一账号在不同设备各保留一份最近完整快照，可以在「恢复云端记录」里选择设备和备份时间。
退出登录/关闭备份保留本机数据；更换账号不会自动上传，需要明确重新开启。

## 数据范围

- 应用每日额度、重复使用的专注任务、睡前管控计划、允许应用、外观和壁纸选择。
- 已结束的正/倒计时、严格番茄钟、睡前管控记录，以及过去日期的有效保护历史。
- 不包含登录凭据、无障碍等系统权限、正在运行的计时、临时放行、当日额度消耗、当日有效保护时间。
- Android 系统提供的历史应用使用事件和诊断试验数据不在首版备份范围内。

恢复为补充合并：任务/专注按 ID，睡前记录按开始时间去重，已有本机记录和设置优先。
恢复前检查当前账号和文件格式，拒绝在专注或睡前管控进行时恢复。
合并后的任务、额度、记录和大小也先校验。历史保护记录重新计算坚持统计，不补算今天。
多个存储采用逐项持久化，不能保证跨文件事务；保存失败可重试，去重使重复恢复保持相同结果。
已在本机删除的任务可能在用户选择旧备份恢复时重新出现。

## 调度与可靠性

网络工作只在应用主进程执行，常驻保护进程不加载网络栈。
设置/历史变化后安排一次网络任务，约 30 秒后具备运行条件；另有 15 分钟周期检查外观、修改窗口、保护历史。
JobScheduler 的时间是最早运行条件，省电、休眠、强行停止和 OEM 后台限制可能延迟任务；不是固定实时同步。
断网/服务不可用保留本机数据，按系统退避调度重试。上传 SHA-256 相同的数据不产生新版本。
服务返回同一快照可幂等确认，旧版本更新其他内容返回 409，并暂停上传，避免覆盖未知版本。
账号、服务器、安装设备分别绑定；上传/恢复过程中账号变化时拒绝写入旧请求结果。
运行时会显示备份状态和最近成功时间。现有登录令牌有效期默认 24 小时，过期需重新登录；首版尚无刷新令牌。

## 本地开发连接

后端项目：`E:\FocusGuardServer\FocusGuardServer`，MySQL 数据库 `focusguard`。
实际凭据存放在后端被 Git 忽略的 `.env`，示例 `.env.example` 不含凭据。
PowerShell 执行 `start-local.ps1` 构建并启动后端，监听 8080。

本轮 APK 通过构建参数 `-PfocusguardApiUrl=http://127.0.0.1:8080/` 指向 USB 转发：

```powershell
E:\AndroidSDK\platform-tools\adb.exe devices
E:\AndroidSDK\platform-tools\adb.exe -s 470e575c reverse tcp:8080 tcp:8080
E:\AndroidSDK\platform-tools\adb.exe -s 470e575c install -r E:\FocusGuard\app\build\outputs\apk\debug\app-debug.apk
```

USB 调试连接和电脑上的后端必须运行。拔线后手机可继续使用本地功能，备份需等重新连接；重连可能需要重新执行 reverse。
这是本地联调，尚未部署公网 HTTPS 服务。后续部署后通过构建参数更换地址，重新登录并开启对应服务器的备份。

## 验证

后端完整测试使用独立数据库 `focusguard_backup_test`；备份集成测试事务回滚，不清空业务库。
覆盖认证、跨账号隔离、相同设备编号的不同账号、幂等重试、旧版本冲突、格式拒绝和较大 JSON 的 MySQL 读写。
Android 新测试覆盖三个任务模式、无效格式、运行状态/临时放行拒绝、当前日保护时间拒绝、合并保留本机变化和重复恢复。
