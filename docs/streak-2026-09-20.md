# Local streak accounting

Superseded on 2026-10-05 by [今日守约](widget-compliance-2026-10-05.md). The 12-hour requirement below describes the preserved legacy policy only.

The logical day runs from local 04:00 to the next local 04:00.
Twelve hours of confirmed accessibility protection and no recorded violation earn a day.
At least one published app restriction or an enabled daily sleep plan must be present.
The first incomplete-length day is preparation rather than failure.

The guard supplies ten-second heartbeat observations. Only adjacent observations within
30 seconds, from the same service session and with consistent wall/elapsed time,
are credited. Both observations must have an eligible plan. Unobserved sleep, killed
processes and reboot gaps do not earn time. This conservative policy needs overnight
device testing: deep sleep may substantially reduce credited time without a wake lock.

AtomicFile plus a file lock coordinates guard, UI and widget processes.
Local records live in noBackupFilesDir. There is no cloud persistence, uninstall
tracking, trusted clock, or guarantee against clearing app data/timezone manipulation.
The UI never retroactively fills old days before feature installation.

Recorded breaks include successful app-limit relaxation, day exemption, early focus
termination, disabling/shortening/rescheduling an enabled sleep plan, and shortening
an active manual session. Ordinary UI exit and two-minute emergency grants do not break.
Rule mutation and streak writes are separate files, not a crash-atomic transaction.

Homepage shows streak and today's confirmed duration. Detail shows recent days and best.
The latest successful settlement is celebrated once; missing older days are settled but
not replayed as a queue of celebration popups. Debug preview does not mutate real records.
Widget opens the homepage, updates during observed heartbeats at minute granularity,
and requests a periodic system refresh. System sleep may defer widget updates.

Validation: debug compilation, 23 Java tests (8 new ledger cases), real-device homepage,
detail and non-mutating celebration preview. Heartbeat credit persisted on device.
Widget provider registered; automatic pin request did not display a confirmation on the
test launcher. Manual launcher placement, dark-mode widget, overnight accounting and
real multi-day automatic celebration remain to be verified.
