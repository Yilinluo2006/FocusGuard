# 睡眠白名单应用临时使用修复

问题：睡眠期间，工具箱在应用额度耗尽时直接拒绝打开；应用临时授权统一拒绝整个专注/睡眠期间；计时路径也忽略期间已有的应用授权。导致白名单应用仍有临时次数但不能申请或使用。

DailyTemporaryAccess 统一申请和消耗判定：正常状态可用；睡眠全局临时退出期间按正常额度规则执行；正在睡眠管控时只允许白名单应用的两分钟日额度授权，桌面不属于此例外；其他专注模式保持原严格规则。每次确认都重新检查白名单和睡眠状态。

工具箱中点击已用尽额度的睡眠白名单应用打开申请浮窗；已有有效授权时可直接进入。到达额度后仍返回睡眠界面，并在睡眠遮挡建立后展示应用申请。放行后只有指定包有额度，睡眠继续限制其他应用。次数与 SleepTemporaryUse 的五次全局退出独立；确认文案注明不扣睡眠全局次数。壁纸备用管控采用同一判定。

回归测试先复现白名单授权被拒绝，修复后 4 项纯 Java 测试通过。独立 Android 包 10 项测试通过，包含最后一次日临时授权、仅指定应用可用、睡眠全局次数保持不变、到期不得申请第六次、撤销白名单即时失去资格、全局睡眠临时退出独立运行，以及旧严格限制回归。测试仅修改独立测试包数据，未调整真实睡眠计划、应用额度或系统时间。

新版已覆盖安装到手机 470e575c。任务、睡眠计划、受限应用配置、历史及同步开关更新前后核对一致。独立测试包卸载，临时诊断无新增日志。真实睡眠时段的界面交互需用户后续实际确认；未将独立规则测试描述为完整整夜验证。
