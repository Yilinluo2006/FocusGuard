## 耗电：亮屏样本

从首次保存基准至回读约 1602 秒（26.7 分钟）。用户确认一直亮屏。

- 电量 60% → 51%；电荷计数 2292 → 1972 mAh；包含 USB 充电时段，因此这只是整机混合场景变化。
- 本应用系统模型估算累计 36.9 → 59.8 mAh，增量约 22.9 mAh；其中分配给屏幕的部分 0.261 → 15.6 mAh，增量约 15.3 mAh，CPU 模型部分约 7.6 mAh。
- /proc 的同 PID 累积 CPU 时间：guard 142.77 秒，主进程 82.08 秒。是亮屏混合场景总 CPU，不能解释为锁屏后台。
- 应用累计部分唤醒锁记录未增长。系统 BatteryStats 电量归因属于模型估算，不能当作独立电流表实测。

该样本不足以决定锁屏后台查询频率；没有修改监控频率。

### 样本有效范围

基准约 21:20:35，回读约 22:09:45，/proc/uptime 相差 2950.66 秒（49.18 分钟）。回读时 USB powered=true，mWakefulness=Awake；锁屏状态与熄屏状态不能混为一谈。

系统历史记录以下关键事件（均为北京时间）：

- 21:20:36 熄屏；21:21:14 抬手唤醒，随后拔线；21:21:19 再次熄屏。
- 21:33:10 指纹唤醒，并出现 plug=usb / +plugged；22:00:08 再次熄屏。
- 22:05:35 指纹唤醒；22:09:45 回读时仍 Awake。以上事件发生在本次采集之前。

BatteryStats 电池供电累计时间增量 715.759 秒（11 分 55.759 秒），电池供电且熄屏累计时间增量 710.856 秒（11 分 50.856 秒）。全窗口有约 31 分钟亮屏，且包含较长 USB 接线时段，所以并非持续 15 分钟以上的纯拔线熄屏样本。历史记录描述系统状态，不用于推断用户是否主动操作或解锁。

### 结果与归因

| 指标 | 基准 → 回读 / 增量 | 解释 |
| --- | --- | --- |
| 整机电量 | 50% → 41% | 49 分钟混合窗口，不全是锁屏掉电 |
| 整机电荷计数 | 1936 → 1564 mAh（下降 372 mAh） | 含 USB、亮屏及其他应用活动 |
| 整机温度 | 40.0 → 37.9°C | 电池服务温度字段 |
| BatteryStats 整机熄屏放电累计 | 188 → 300 mAh（增加 112 mAh） | 不能全归因本应用 |
| 应用电池供电、熄屏 CPU 模型估算 | 3.84 → 4.25 mAh（约增加 0.41 mAh） | 明确取 on battery, screen off/doze 分项 |
| 应用全状态 CPU 模型估算 | 45.6 → 54.4 mAh（约增加 8.8 mAh） | 含接线亮屏；其中 not on battery, screen on 15.4 → 23.7 mAh |
| 应用部分唤醒锁 | blamed 892ms、actual 2616ms，前后不变 | 本窗口未观察到增长 |
| RESTART_PROTECTION 唤醒闹钟 | 1 → 1 次 | 本窗口未观察到增长 |
| BatteryStats 进程 CPU | guard 增加 2.15 秒；主进程增加 5.48 秒 | 与电池供电统计结合看；不等同于全窗口 /proc 累积值 |
| /proc 同进程 CPU（全窗口） | guard 174.51 秒（单核 5.91%）；主进程 95.06 秒（单核 3.22%） | PID 与 starttime 均一致；含接线亮屏时段 |

/proc CPU 使用原采样脚本的 Android USER_HZ=100 换算；百分比是单核等效平均占用，不是整机多核利用率。模型数值有舍入与采集延迟，CPU、唤醒锁指标各有统计口径；不能把模型耗电当作独立电流表实测。参考：[Android 电力统计与功耗模型](https://source.android.com/docs/core/power)、[dumpsys BatteryStats](https://developer.android.com/tools/dumpsys)。

### 本次决定

保持现有监控频率。电池供电熄屏分项只增加约 0.41 mAh CPU 模型耗电，未观察到应用部分唤醒锁或重启唤醒闹钟增长；这批数据没有支持因锁屏持续高 CPU 而立即调低频率。整机熄屏放电仍值得另行排查，但不能归咎于奶蛙，也不能据此宣称待机耗电已全面通过。

本轮只完成只读采样与报告更新，没有更改监控代码、重新安装应用或触碰正式数据。由于没有复现明确的锁屏高耗电症状，诊断停留在基准测量与归因，没有进入假设修复阶段。若继续量化纯待机耗电，应使用新的样本名前缀，保留本次原始记录，取得至少 15–30 分钟连续拔线熄屏区间，并用系统历史核实亮屏/接线事件后再比较。

## 监控代码检查

- 壁纸守护共用单个 worker，750ms 检查；无障碍正常、无壁纸权限、非交互或锁屏时跳过 queryEvents；原有短周期仍可能执行权限/健康读写。
- 无障碍恢复检查 2 秒，锁屏时停止应用计时并跳过 queryEvents。
- 保护心跳 10 秒；设备同步 15 秒；界面刷新在暂停后注销。
- 守护壁纸按可见/Surface变化绘制，不连续逐帧渲染；未发现应用直接持有长期 CPU 唤醒锁。
- 本次锁屏回读后保持监控频率；若后续有效样本支持优化待机周期，改动须验证解锁恢复和拦截延迟。
